# 업무 규칙

고양시 장애인복지관 사회복무요원의 휴가, 나눔가게 오전·오후 배정, 식당지원 일정을 관리하는 앱 **장복인간**의 규칙이다. 규칙을 바꾸면 이 문서도 같이 고친다. 실행 방법은 [README](../README.md)에 있다.

## 용어

- **활동**: 나눔가게, 식당지원처럼 따로 운영하는 일. 코드의 `Activity` enum으로 정하고, 관리자는 활동마다 가입 직원만 바꾼다.
- **업무**: 활동의 특정 날짜에 할 일. 지금은 나눔가게의 오전·오후 업무만 자동으로 만든다.
- **직군**: 식당, 운영지원, 운영지원(기계실), 3층, 발달지원 중 하나. 로그인 권한(직원·관리자)과는 별개다.
- 인원에 정원은 없다. 직원은 들어오고 나가면서 늘거나 줄 수 있다.

## 계정과 권한

- 직원 계정은 관리자만 만든다. 한글 이름(공백 없이 1~30자)이 로그인 이름이고, 같은 이름은 등록할 수 없다.
- 비밀번호는 8~20자, 영문·숫자·`!@#$%_-`만 쓸 수 있다. 본인이 프로필에서 바꾼다.
- 본인 휴가·선호도·프로필·교환은 로그인한 계정 기준으로만 처리한다. 요청에 다른 직원 ID를 넣어도 무시한다.
- 관리자 화면(`/admin/**`)은 주소를 직접 입력해 들어가고, 직원이 접근하면 403이다. 일반 화면에는 관리자 메뉴를 보여주지 않는다.
- 로그인하면 관리자·직원 모두 나눔가게 화면으로 간다. 같은 브라우저에서는 90일 동안 자동 로그인되고, 비밀번호를 바꾸거나 로그아웃하면 풀린다. 관리자 계정은 앱을 다시 시작하면 다시 로그인해야 한다.

| 기능 | 직원 | 관리자 |
| --- | --- | --- |
| 본인 휴가, 나눔가게 선호도, 지원일 교환 | 가능 | - |
| 다른 직원 휴가 입력 | - | 가능 |
| 직원 등록·제외, 직군 변경, 활동 가입 관리 | - | 가능 |
| 휴일, 식당지원표, 식당지원 필요 인원 | - | 가능 |
| 프로필 사진 | 본인 것 | 모든 직원 |
| 복무 기간 수정 | 본인 것 | 조회만 |

## 복무 기간

- 소집일 기본값은 계정 등록일이다. 본인이 프로필에서 실제 소집일을 고친다.
- 소집해제일은 소집일로부터 21개월 되는 날의 전날로 자동 계산한다(그 달에 같은 날이 없으면 말일). 실제 날짜가 다르면 본인이 고칠 수 있다. 소집일보다 늦고 오늘 이후여야 한다.
- 소집일부터 소집해제일까지만 배정 대상이다. 관리자가 직원을 제외하면 그날부터(08:49 이후면 다음 날부터) 빠진다. 이미 확정된 배정은 그대로 둔다.
- 사진은 2MB 이하 JPG·PNG·HEIC를 512px JPEG로 줄여 저장한다.

## 마감 시각

모든 시각은 한국 시간 기준이고, 마감은 그 날짜 **당일** 기준이다.

| 항목 | 기준 |
| --- | --- |
| 휴가 입력(본인·관리자), 휴일 지정·해제 | 당일 08:49 전 |
| 식당지원표 수정, 교환 요청·수락 | 당일 08:49 전 |
| 직원 제외, 식당지원 필요 인원 변경 | 08:49 전이면 당일부터, 이후면 다음 날부터 |
| 직군 변경, 활동 가입·탈퇴, 나눔가게 선호도 | 바로 반영, 확정된 배정은 유지 |
| 나눔가게 자동 배정 | 근무일 08:49:10 |
| 배정 결과 공개 | 08:50 |
| 만료된 교환 요청 삭제 | 매일 09:00 |

미래 날짜의 휴가와 식당지원표는 미리 입력할 수 있다.

## 근무일과 휴가

- 토·일요일은 쉬는 날이다. 관리자가 평일을 휴일로 지정할 수 있고 사유는 선택이다.
- 휴일로 바꿔도 그날 휴가 신청은 지우지 않는다. 휴일을 풀면 다시 적용된다.
- 휴가는 직원·날짜별로 하나 저장하고 모든 활동에 똑같이 적용한다. 취소는 "정상 출근"으로 저장하는 것이다.
- 훈련소·직무교육처럼 복지관에 나오지 않는 기간은 관리자가 직원 관리 화면에서 시작일~종료일로 "교육·훈련"을 등록한다(주말·휴일 제외, 60일 이내). 직원은 직접 고를 수 없다.

| 상태 | 오전(09–14시) | 오후(14–18시) |
| --- | --- | --- |
| 정상 출근 | 가능 | 가능 |
| 연차, 병가, 특별휴가 | 불가 | 불가 |
| 교육·훈련(관리자 입력) | 불가 | 불가 |
| 오전 반차 | 불가 | 가능 |
| 오후 반차 | 가능 | 불가 |

## 복무 현황

계급과 호봉은 소집일로 계산하고 따로 저장하지 않는다. 소집한 달을 1개월째로 센다.

| 복무 개월 | 계급 |
| --- | --- |
| 1–2개월 | 이병 |
| 3–8개월 | 일병 |
| 9–14개월 | 상병 |
| 15개월부터 | 병장 |

- 호봉은 그 계급 안에서 몇 번째 달인지다(9개월째 = 상병 1호봉).
- 직원 프로필에 계급·호봉, 소집해제까지 남은 날(D-n), 복무 진행률(소수점 7자리, 실시간)을 보여준다. 다른 직원도 볼 수 있다.
- 직원 목록은 계급이 높은 순, 같으면 소집일이 빠른 순으로 보여준다.

## 월급 예상

본인만 "내 월급 조회"에서 본다. 매달 10일에 지난달 근무분을 받는다.

- **봉급**: 그 달 계급의 월 보수(`app.service-pay.monthly-pay`, 2026년 이병 75만·일병 90만·상병 120만·병장 150만 원). 소집월과 소집해제월은 복무한 날만큼 일할 계산한다. 휴가로는 깎이지 않고, 병가가 복무 기간 통산 30일을 넘은 날만 빠진다.
- **교통비**: 근무일마다 본인이 정한 금액(기본 3,000원, 본인이 변경). 연차·병가·특별휴가·교육·훈련인 날은 빠진다. 반차는 나온다.
- **식비**: 근무일마다 9,000원(`app.service-pay.daily-meal`). 교통비가 빠지는 날과 오전 반차인 날은 빠진다.
- 아직 지나지 않은 날은 정상 출근으로 계산한 예상 금액이다.
- "내 휴가 일정"에서 본인의 휴가 사용 내역(종류별 횟수, 연차 사용 일수, 날짜별 세부 내역)을 본다.

## 활동 가입

- 직원을 등록하면 직군에 따라 자동 가입한다. 식당 외 직군은 식당지원에, 운영지원·기계실은 나눔가게에 가입한다.
- 그 밖의 가입·탈퇴는 관리자가 활동 화면에서 직원별로 한다. 식당 직군은 나눔가게와 식당지원 모두 가입할 수 없다.
- 직군이 바뀌어 자격을 잃으면 그 활동에서 바로 탈퇴하고 관련 데이터(선호도, 앞으로의 식당지원 일정)도 정리한다. 직군이 돌아와도 다시 자동 가입하지 않는다.
- 휴가나 당일 식당지원은 가입을 바꾸지 않는다. 그날 배정 후보에서만 빠진다.

## 나눔가게 오전·오후 배정

### 그날 배정할 사람

1. 나눔가게에 가입했고 그날 근무 기간인 직원
2. 그날 식당지원을 맡은 직원은 뺀다.
3. 연차·병가는 빼고, 반차는 근무하는 시간대 후보로만 남긴다.

### 인원 나누기

- 남은 인원으로 오전·오후 인원을 정한다. 기본은 오전이 반올림해서 절반(3명이면 2:1, 5명이면 3:2)이고, 1명이면 그 사람이 오전·오후를 모두 맡는다.
- 인원수별 예외는 `application.yml`의 `app.sharing-shop-quotas`로 정한다. 합계는 그 인원수와 같아야 한다.
- 기계실은 오전·오후 각각 한 명이 상주해야 한다. 상주하는 사람은 그 시간대 나눔가게에서 빠진다. 상주할 사람이 없으면 경고한다.
- 조합을 고를 때는 나눔가게 시간대가 비지 않는 것, 기계실 상주, 한 사람이 두 곳을 겸하지 않는 것, 모두 배정되는 것, 목표 비율, 선호 순으로 따진다.
- 반차 때문에 한쪽에 사람이 몰리면 목표 비율을 바꿔서라도 모두 배정하고, 비는 시간대는 경고한다.

### 시간대 선호도

- 직원마다 오전·오후·상관없음 중 하나를 저장한다. 나눔가게 전용이고 날짜와 상관없이 유지된다.
- 마감이 없고 다음 추첨부터 반영한다. 나눔가게에 가입한 사람만 바꿀 수 있다.
- 조건이 같으면 선호를 많이 맞추는 조합을 고르고, 그래도 같으면 무작위로 정한다. 먼저 입력했다고 유리하지 않다.
- 반차와 맞지 않는 선호는 무시된다. 누적 횟수를 맞추는 순번제는 없다.

### 배정 결과

- 매일 08:49:10과 앱 시작 때 오늘 배정이 없으면 만든다. 한 활동 배정이 실패해도 다른 활동은 계속 진행하고 오류를 로그에 남긴다.
- 확정된 배정은 다시 추첨하거나 지우지 않는다. 배정 당시 이름과 근무 상태를 함께 저장한다.
- 결과는 08:50부터 화면에 보인다. 그 전에는 참여 인원과 예정 인원, 남은 시간을 보여준다.

## 식당지원

- 추첨하지 않는다. 관리자가 매달 받은 지원표를 날짜별로 입력한다.
- 기본 필요 인원은 하루 2명이고 관리자가 바꿀 수 있다. 날짜별 실제 인원은 필요 인원과 달라도 저장하고, 다르면 경고만 한다.
- 식당지원에 가입했고 그날 근무하며 휴가·반차가 없는 직원만 넣을 수 있다.
- 나중에 휴가를 넣어 지원과 겹치면 경고한다. 휴가는 자동으로 취소하지 않고, 지원표를 고치거나 교환으로 해결한다.
- 지원표가 비어 있다고 아무나 빼지 않는다. 등록된 사람만 그날 나눔가게에서 빠진다.

## 식당지원 교환

두 직원이 **서로의 다른 날짜를 맞바꾸는** 방식이다. 홍길동 10일 ↔ 김민수 11일을 교환하면 김민수가 10일, 홍길동이 11일을 맡는다.

- 내 지원일을 고르면 그날과 바꿀 수 있는 상대 일정만 보여준다. 오늘부터 3개월 뒤까지 보여준다.
- 상대가 수락해야 바뀌고, 그 전까지는 원래 지원표대로 간다. 보낸 사람은 취소, 받은 사람은 거절할 수 있다.
- 수락할 때 마감, 담당자, 가입, 근무 기간, 휴가, 다른 지원 겹침을 다시 확인한다. 그 사이 관리자가 지원표를 바꿨다면 수락할 수 없다.
- 교환이 되면 두 날짜에 걸린 다른 요청은 지운다. 동시에 수락해도 한 번만 반영된다.
- 두 날짜 중 이른 날의 08:49가 마감이다. 지나면 수락할 수 없고, 매일 09:00에 지운다.

## 화면 주소

주소는 자원 이름으로 정하고, 바꾸는 요청은 PUT(저장)·DELETE(삭제)·POST(생성·상태 변경)로 구분한다. 화면 폼은 POST에 숨은 `_method` 값을 실어 보낸다.

| 화면 | 주소 |
| --- | --- |
| 나눔가게 | `/sharing-shop` (관리자: `/admin/sharing-shop`) |
| 내 휴가 | `/leave` (`/`에서 이동) |
| 내 월급 조회 | `/pay` |
| 전체 휴가 일정 | `/leave/team` |
| 내 식당지원 일정·교환 | `/cafeteria-support` |
| 식당지원표 | `/cafeteria-support/schedule` (관리자 입력: `/admin/cafeteria-support`) |
| 직원 목록·프로필 | `/employees`, `/employees/{id}`, `/employees/me` |
| 관리자 | `/admin/leave`, `/admin/employees`, `/admin/holidays`, `/admin/activities` |

| 요청 | 주소 |
| --- | --- |
| 휴가 저장 | `PUT /leave/{date}`, 관리자 `PUT /admin/employees/{id}/leave/{date}` |
| 휴일 지정·해제 | `PUT`·`DELETE /admin/holidays/{date}` |
| 활동 가입·탈퇴 | `PUT`·`DELETE /admin/activities/{code}/members/{employeeId}` |
| 직원 등록·제외 | `POST /admin/employees`, `POST /admin/employees/{id}/retirement` |
| 직군 변경 | `PUT /admin/employees/{id}/work-group` |
| 사진·비밀번호·복무 기간 | `PUT /employees/{id}/photo`·`password`·`service-period` |
| 나눔가게 선호도 | `PUT /sharing-shop/time-preference` |
| 하루 교통비 | `PUT /pay/transport-fee` |
| 교육·훈련 기간 등록 | `POST /admin/employees/{id}/trainings` |
| 식당지원표·필요 인원 | `PUT /admin/cafeteria-support/{yyyy-MM}`, `PUT /admin/cafeteria-support/requirement` |
| 교환 요청·수락·거절 | `POST /cafeteria-support/exchange-requests`, `POST .../{id}/acceptance`, `DELETE .../{id}` |
